好的，以下是修改后的技术方案，将“知识图谱持续扩建”替换为 **Human-in-the-Loop（人机协同）** 机制。

---

## 项目技术方案

### 一、整体架构

系统采用**分层并行调度架构**，分为数据管线、多智能体协作、记忆与工具三层。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           用户输入                                      │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        调度Agent（协调层）                               │
│              意图解析 → 任务分解 → 构建依赖图 → 并行调度                  │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
        ┌───────────────┬───────────┼───────────┬───────────────┐
        ▼               ▼           ▼           ▼               ▼
┌───────────┐   ┌───────────┐ ┌───────────┐ ┌───────────┐ ┌───────────┐
│ 辨证Agent │   │ 方剂Agent │ │ 针灸Agent │ │ 养生Agent │ │SearchAgent│
└─────┬─────┘   └─────┬─────┘ └─────┬─────┘ └─────┬─────┘ └─────┬─────┘
      │               │           │           │               │
      └───────────────┴───────────┴───────────┴───────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                     调度Agent（汇总层）                                  │
│         收集结果 → 冲突检测 → 协调裁决 → 融合生成最终答案                │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      知识图谱 + 记忆 + 人机协同层                        │
│         Neo4j图谱 │ Redis短期记忆 │ Neo4j长期记忆 │ Web Search          │
│                    │  人工审核队列（Human-in-the-Loop）│                │
└─────────────────────────────────────────────────────────────────────────┘
```

### 二、多智能体并行调度机制

**核心流程**：

```
用户输入
    │
    ▼
┌─────────────────────────────────────────┐
│ 调度Agent：解析意图，识别实体            │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 构建任务依赖图                           │
│ 例：方剂Agent ──依赖──→ 辨证Agent       │
│     针灸Agent ──依赖──→ 辨证Agent       │
│     养生Agent ──无依赖──→ 可直接执行    │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 阶段一：执行无依赖任务（并行）            │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐ │
│ │ 辨证Agent│ │ 养生Agent│ │SearchAgent│ │
│ └────┬─────┘ └────┬─────┘ └────┬─────┘ │
│      └────────────┼────────────┘       │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 阶段二：执行依赖任务（并行）              │
│ ┌──────────┐ ┌──────────┐              │
│ │ 方剂Agent│ │ 针灸Agent│              │
│ └────┬─────┘ └────┬─────┘              │
│      └────────────┼────────────┘       │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 调度Agent：汇总 → 冲突检测 → 最终答案    │
└─────────────────────────────────────────┘
```

**并行执行策略**：

| Agent类型 | 并行策略 | 依赖关系 |
| :--- | :--- | :--- |
| 辨证Agent | 阶段一独立并行 | 无依赖 |
| 养生Agent | 阶段一独立并行 | 无依赖 |
| SearchAgent | 阶段一独立并行 | 无依赖 |
| 方剂Agent | 阶段二并行 | 依赖辨证结果 |
| 针灸Agent | 阶段二并行 | 依赖辨证结果 |
| 审核Agent | 后置串行 | 依赖其他Agent输出 |

**超时与降级**：每个Agent设置独立超时阈值（10-20秒），超时后返回降级结果，不影响其他Agent执行。

---

### 三、冲突检测与协调机制

| 冲突类型 | 检测方式 | 协调策略 |
| :--- | :--- | :--- |
| 安全冲突 | 审核Agent检出 | 安全优先，否决冲突推荐 |
| 辨证冲突 | 多Agent结果对比 | 以辨证Agent为准，触发重算 |
| 信息冲突 | 结果一致性校验 | 按置信度/来源优先级裁决 |

---

### 四、Human-in-the-Loop（人机协同）机制

系统在关键环节引入人工审核与干预，确保医疗场景下的安全性与可靠性。

**核心流程**：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Human-in-the-Loop 流程                           │
└─────────────────────────────────────────────────────────────────────────┘

  Agent输出结果
       │
       ▼
┌─────────────────────────────────────────┐
│ 置信度评估模块                           │
│ 根据置信度分数分流：                     │
│ • ≥0.9 → 自动通过                       │
│ • 0.6-0.9 → 进入待审核队列              │
│ • <0.6 → 返回“无法回答”或降级回答       │
└─────────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────────┐
│ 人工审核队列（Web审核面板）              │
│ • 专家查看Agent输出                     │
│ • 确认/修正/驳回                        │
│ • 填写修正意见                          │
└─────────────────────────────────────────┘
       │
       ├── 通过 ──→ 直接返回用户
       │
       ├── 修正 ──→ 返回修正版答案，同时将修正内容存入知识库
       │
       └── 驳回 ──→ 触发降级回答或转人工客服
```

**三种触发场景**：

| 触发场景 | 说明 | 处理方式 |
| :--- | :--- | :--- |
| **低置信度回答** | 模型对答案不确定（如输出含“可能”“建议咨询医生”） | 进入审核队列，专家确认后回复 |
| **安全敏感问题** | 涉及方剂推荐、针灸操作、药物禁忌等 | 强制人工审核，未经审核不输出 |
| **用户主动请求** | 用户点击“请专家核实”按钮 | 进入审核队列，专家介入 |

**审核反馈的闭环利用**：

```
专家修正意见
       │
       ▼
┌─────────────────────────────────────────┐
│ 知识更新模块                             │
│ • 修正错误三元组 → 更新Neo4j图谱         │
│ • 补充缺失知识 → 新增实体/关系           │
│ • 优化Prompt → 更新Harness层Prompt模板  │
└─────────────────────────────────────────┘
       │
       ▼
  系统持续进化
```

### 五、记忆管理

| 记忆类型 | 存储位置 | 内容 | 淘汰策略 |
| :--- | :--- | :--- | :--- |
| 短期记忆 | Redis | 会话上下文、临时结果 | 会话结束清除 |
| 长期记忆 | Neo4j | 用户历史、专家审核记录 | 永久保留（匿名化） |
| 工作记忆 | 黑板 | Agent中间结果、冲突记录 | 任务完成清除 |

**审核记录的价值留存**：每位专家的修正意见作为高质量训练数据留存，用于后续模型的Few-shot示例和Prompt优化。

### 六、Harness层设计

封装千问API调用，包含以下模块：

| 模块 | 功能 |
| :--- | :--- |
| 动态Prompt生成 | 根据任务类型自动生成定制Prompt |
| Few-shot示例库 | 为16类实体分别维护示例（含人工审核通过的优质案例） |
| 输出校验 | 实体类型验证、格式规范 |
| 本体按需注入 | 根据任务动态注入相关本体定义 |
| 置信度评估 | 对模型输出进行置信度打分，低于阈值进入审核队列 |
| 断点续传 | 支持大规模抽取的稳定处理 |
